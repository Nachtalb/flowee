Flowee

A configurable ticket flow for AI agent teams, with the human's inbox in a chat.

A board specifies, developers build, testers test, and each step is a command checked against a statechart. What needs you arrives as a card in Telegram or your terminal; you answer by replying.

How it works

Agents take the work. The flow decides what comes next.

Agents change tickets only through Flowee's HTTP API with a small client, flowee.py. An agent's run is short: take work with next, do it, hand it over, stop. The tracker is the record: a ticket's state is a label on its issue, and every command re-reads the issue.

  • board

    Plans and specifies the tickets, sends work back, and is the only one who asks the owner.

  • developer

    Builds what a ready ticket asks for and hands it to testing.

  • tester

    Tests a handed-over ticket's build and passes or fails it.

  • owner

    You. The tickets that need a human (tests, questions, decisions) reach you as cards; your answer goes back to the board.

One ticket's way through the flow

  1. needs triageboardThe board specifies it with its acceptance criteria.
  2. readydeveloper's queueWaits for a developer's next.
  3. in developmentdeveloperCommits with green gates, then hands it off.
  4. ready for testingtester's queueWaits for a tester's next.
  5. testingtesterPassed or failed; a fail goes back to development.
  6. board reviewboardA pass with an owner check comes back to the board.
  7. human reviewowner's cardThe board escalates; the card reaches you in the chat and you reply.
  8. closeddoneWith your answer, the board approves it.

Features

Everything a project needs is one JSON document.

Repositories, flow, project key, texts and chat: one document per workspace. It never holds a secret, only its name.

GitHub and GitLab

GitHub, and GitLab on gitlab.com or self-managed. One workspace may cover several repositories and mix both; its tickets are written alias#12.

Your inbox: Telegram or terminal

Cards in a private chat, a group or one topic of a forum group, or in flowee-tui over SSH and in tmux. Both at once are one conversation in two windows.

Webhooks, not polling

Flowee registers each repository's webhook itself and re-reads only the ticket a delivery names. Without webhooks it polls the tracker every minute.

One statechart, your switches

One XState chart, openable in Stately, with optional parts: feature branches and pull requests, versioning, UI review, dependency tickets, user feedback. Own states come as extensions.

An own bot per workspace

In the managed mode people set up their workspaces with a wizard in the chat, with the instance bot or an own bot Flowee creates, carrying the project's name and photo.

Export and import

Export your workspaces as a file from /workspaces, send a .json file to the bot to create or replace one. Exports never contain a secret.

  • pullRequests a branch and a pull request per ticket
  • releases test cards held until released
  • uiReview UI changes go past the owner
  • dependencyTickets one ticket per dependency pull request
  • userFeedback feedback triaged automatically or by a human

Run it

Four ways to use Flowee.

INSTALL.md is the procedure for each of them, written for an agent that leads you through it and readable as it is.

  1. 1

    A hosted instance

    Someone else's Flowee; you only talk to its Telegram bot. Needs a tracker token and the instance's URL.

    This instance is managed: in a private chat with @{{bot}}, /setup starts the wizard for those it lets create workspaces.it lets the people its operator chose create workspaces.

    This instance serves only the workspaces its operator configured.

  2. 2

    Container

    The published image (amd64, arm64) under Docker, Podman or wslc. No public address needed: it polls, or gets webhooks behind a reverse proxy.

    docker pull ghcr.io/nachtalb/flowee:latest
  3. 3

    One executable

    The same program built from a clone with bun 1.4+, as one file or with bun run start; its data is one directory.

    bun run compile -- --target bun-linux-x64 --outfile flowee
  4. 4

    Your own Cloudflare deployment

    A Worker on your Cloudflare account at its *.workers.dev URL; nothing to keep running yourself.

    bun run deploy
