Flowee

A configurable ticket flow for AI agent teams, with the human's inbox in a chat.

A board specifies, developers build, testers test, and each step is a command checked against a statechart. What needs you arrives as a card in Telegram or your terminal; you answer by replying.

How it works

Agents take the work. The flow decides what comes next.

Agents change tickets only through Flowee. A run is short: take work, do it, hand it over, stop.

  • board

    Specifies the tickets; the only one who asks the owner.

  • developer

    Builds what a ready ticket asks for.

  • tester

    Tests the build: pass or fail.

  • owner

    You. What needs a human reaches you as a card.

One ticket's way through the flow

  1. needs triageboard
  2. readydeveloper's queue
  3. in developmentdeveloper
  4. ready for testingtester's queue
  5. testingtester
  6. board reviewboard
  7. human reviewowner's card
  8. closeddone

Features

Everything a project needs is one JSON document.

One document per workspace. It never holds a secret.

GitHub and GitLab

GitLab on gitlab.com or self-managed. One workspace may cover several repositories.

Your inbox: Telegram or terminal

Cards in a private chat, a group or a topic, or in the terminal with flowee-tui.

Webhooks, not polling

Flowee registers the webhooks itself. Without them it polls every minute.

One statechart, your switches

Pull requests, versioning, UI review, dependency tickets, user feedback: each optional.

An own bot per workspace

Set up with a wizard in the chat, on the instance bot or a bot of the project's own.

Export and import

A workspace is a .json file: export it, send it back to replace it.

Run it

Four ways to use Flowee.

INSTALL.md has the procedure for each.

  1. A hosted instance

    Someone else's Flowee; you only talk to its bot.

    This instance is managed: in a private chat with @{{bot}}, /setup starts the wizard for those it lets create workspaces.it lets the people its operator chose create workspaces.

    This instance serves only the workspaces its operator configured.

  2. Container

    The published image under Docker or Podman. No public address needed.

    docker pull ghcr.io/nachtalb/flowee:latest

  3. One executable

    Built from a clone with bun; its data is one directory.

    bun run compile -- --target bun-linux-x64 --outfile flowee

  4. Your own Cloudflare deployment

    A Worker on your own account; nothing to keep running.

    bun run deploy
